# Application updates and versioned releases

Brk 0.0.1 introduces signed in-app download and restart installation, a sidebar button, immutable versioned downloads, and curated release notes. Older 0.1.0 copies need one manual installation because they contain no updater.

## Verification

- The clean integrated source passed all 1184 Swift tests, with 2 designed skips and 0 failures. Run `python3 scripts/with-batch-locks.py --lock /tmp/brk-batch-build.lock -- swift test`.
- `scripts/run-native.py updater-release-001 --set smoke,sidebar,core,windows --only TextLayout` ran all 37 requested scenarios with no failures or omissions. The native phase drained its owned processes before releasing its lock.
- `scripts/verify-app-update.py --app <built-app> --sign-tool <Sparkle-sign_update> --out <outside-repo>` uses disposable apps, data, keys, APFS/LZFSE DMGs, and the production appcast renderer. A physical button click downloaded and replaced build 42, version 0.1.0 with build 44, version 0.0.1, relaunched a different PID, and retained the same Space ID/title and data directory. Damaged signatures and an unavailable download server retained the original app and process.
- Actual light and dark native frames place the update button at x 8, y 694, width 212, height 24 in a 228-point sidebar of a 1280 by 776 window, matching the Arc 1.170 reference. The text uses 12-point regular system type. Tabs, expanded media players, floating sidebars, and neighboring Space pages reserve the updater's region.
- Six Python release checks pass with `python3 -m unittest discover -s scripts/tests -p 'test_release.py'`. They execute the inline publisher and cover immutable reruns, different-code version reuse, publication order, and an older build arriving after a newer Latest release. The Latest regression failed before the fix and passes after it. Workflow shell syntax checks pass.
- Sparkle 2.10.1 embedding retains the universal framework, helper apps, XPC services and their entitlements. Strict ad hoc signatures pass. Developer ID signing, notarization, final DMG signing, and published asset inspection are separate production artifact checks in the Release workflow.

## Boundaries

Sparkle owns authentication, extraction, replacement, privileges and relaunch. Brk keeps its existing ordered state flush and engine shutdown. A staged installer may act on eventual process exit, including the existing shutdown timeout; exit status is not an installation gate. Ad hoc development signing omits hardened library validation; Developer ID signing retains it.

Idle button geometry and typography were measured. Fill and stroke opacity are fitted to reference pixels; Arc hover, pressed and busy-state pixel identity remains unmeasured. This does not claim pixel identity across every updater state.

Parallel implementation and independent reviews used the available Codex family after the user authorized fallback from unavailable Grok and out-of-quota Claude. Reviews found and fixed the ad hoc launch failure and backwards Latest promotion. Full logs, manifests and screenshots live outside the repository at `~/brk-evidence/release-updater-20261114/`.
