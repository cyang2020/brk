# BrkCore page resources and Chrome Web Store

Brk 0.0.2 keeps one live page for a logical tab and profile across windows. The previous window shows a handoff placeholder. Idle pages can freeze and be reclaimed; returning to a reclaimed page reloads it. Add Extension opens Chrome Web Store, and installed extensions appear without Refresh. Native installation sheets show the full title. Manifest-validated extension settings open or select a tab in the owning profile.

The framework requires embedding interface 3. Patches 0030 through 0033 reproduce the source tree at native commit `6dca5a74b4` from the previous official engine baseline. Both official archives were published, downloaded with the canonical verifier and checked against the header fingerprint in `engine/artifacts.json`.

Reopening settings selects the same tab and preserves its input. - The final package, built from the downloaded interface 3 engine, passed all 60 cases with no failures or omissions. The four batches cover smoke/core, pages/find plus Core-pip, downloads/sites and commandbar. Combined replay: `python3 scripts/run-native.py resource-store-review --set smoke,core,pages,find,downloads,sites,commandbar --only Core-pip`.
- A real default-policy run used unchanged clocks and the production 300/1800-second thresholds. Actual freezing was first observed at 300.3 seconds and automatic discard at 1,832.5 seconds. Physical clicks reloaded the normal page and recovered keyboard focus; the protected form kept its original document and typed input. The app exited 0. The later options change leaves the Swift resource policy, native freeze/discard code and same-tab transfer method unchanged; those files and methods were compared byte for byte.

The original settings restore failure reproduced in a unit test. After fixing the user/restore URL rule, the exact real saved state restored the same settings item in two normal launches. Real keyboard input and all six enabled DNR rulesets were checked. Ordinary webpage URL restrictions remain unchanged.
