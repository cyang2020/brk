## 怎么跑

新的 checkout 先建 CEF 链接，再构建：

```sh
ln -s /Users/administrator/.cache/arc-spike-swift/.cef .cef
python3 scripts/with-batch-locks.py --lock /tmp/brk-core-native.lock --lock /tmp/brk-batch-build.lock --timeout 55 -- scripts/build.sh
```

完整或局部原生回归（带锁、带时限、记录源码和二进制哈希）：

```sh
python3 verify/completion/browser-basic-parent/run-native.py <唯一名字> --run-timeout 900
python3 verify/completion/browser-basic-parent/run-native.py <唯一名字> --only T13,BB1 --run-timeout 600
```

不带锁的老跑法（写到 `verify/swift/`）：

```sh
SKIP_BUILD=1 scripts/e2e.sh --only 2,4,R6
```

台账检查：

```sh
python3 scripts/check-completion.py
python3 scripts/check-completion.py --require-complete
```

环境事实：这是 SSH 登录的 shell，但能开窗口和截屏（`screencapture`、`open -a` 可用），屏幕常是锁着的，按窗口 id 截自己的窗口照样行。REA 6.7.0 已装并注册给 Claude Code 和 Codex；Ghidra 12.1.4 在 `~/.local/ghidra/ghidra_12.1.4_PUBLIC`，JDK 21 在 `/opt/homebrew/opt/openjdk@21`，用 rea 时设 `GHIDRA_INSTALL_DIR` 和 `JAVA_HOME`。Arc 1.170 的原始包在 `~/.cache/arc-target/Arc.app`。

## 协作规则

- 父进程独占 `docs/completion/features.json`、`docs/completion/plan.md`、批次 manifest 和 `.audit/arc-clone.tsv`。工人只写自己的 checkout，报告和提案放 `verify/completion/<片名>/`。
- 完整构建和原生测试必须拿锁。原生测试跑着的时候不改源码。只结束自己的进程，不杀别人的。
- 不读用户真实浏览器的 profile、cookie、密码；不改默认浏览器；不对外发布。
- 一个开关被持久化、一个菜单项被禁用、一个占位页、一次构建通过，都不算功能完成。完成要有实际行为的测试或原生场景收据。
- 决策和失败尝试都写进 `.audit/arc-clone.tsv`，用 `~/.claude/skills/show-me-your-work/scripts/log.sh` 追加。
- 新的审查或复查都起新的 delegate，不要往已完成的 delegate 里续消息。
