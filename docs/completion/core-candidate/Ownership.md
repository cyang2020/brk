# Ownership and operation contracts

## Shared rows, independent live pages

`Doc.tree` remains the single shared sidebar structure. A logical tab stores its stable ID, launch URL, pinned anchor, and user title. `WindowTabState[window][tab]` owns that window's current URL, observed title, and loaded demand. Browser observations update only their slot. A title callback in a background window cannot overwrite another window's address. Sidebar projection prefers the local realization's observation, then the logical row's seed. User-defined titles remain shared and override observed titles.

Selecting an existing tab first creates or resumes that window's slot. Its first URL is the tab's shared launch URL. A newly requested navigation affects only that slot. A deliberate “open this address in another window” passes the address explicitly. We do not synchronize arbitrary page redirects or form state between windows. This is a proposed Brk policy, not a statement about Arc.

`WindowDoc` stores standard-window slot URLs and split focused-pane selection. Split membership, orientation, and fractions stay shared for this batch, because those are properties of the shared split item; focus is per window. On v2 migration, each restored standard window seeds its selected slots from the existing tab URL and split focus. Other rows remain lazy. Current slots are saved only for standard windows and validated against existing tree membership. Runtime tokens, callbacks, native hosts, and private state are never serialized.

Closing a standard window retires its slots and leaves shared rows and other windows' browsers intact. The existing Today Close/Archive command still removes the shared logical tab and retires every corresponding slot. Pinned Close and Keep removes loaded demand for that logical tab in all windows but keeps the row. The UI must make this shared close behavior explicit; a future local “dismiss from this window” is a distinct command, not an implicit alternate path. Page-initiated `window.close()` removes only the originating realization and its selected card, unless its scratch tab has no other owner. It never closes another window's realization.

A background tab retains its creating window's slot and receives observations without native focus. When a global slot's owner window closes, a delayed popup from a retiring browser is rejected. Scratch tabs and Peek belong to their existing `ContainerScope.window`; their slots retain that owner even while hidden. Private modifier opens and hidden popups remain within the private container. Open In keeps the current reload/new-identity behavior when context changes. In-context live transfer would require an explicit slot move and tested new owner; it is not silently promised by this batch.

## Event origin and native focus

The engine's browser record contains its immutable `PageSlot`. This is the origin for page requests, downloads, and navigation observations. There is no `window(showing:)` search. Keyboard events additionally validate that the current embedded surface is attached to the registered native window for `slot.window`; a detached, hidden, retired, or foreign surface cannot dispatch a shortcut. Background popups use logical owner provenance instead of failing the keyboard visibility check.

Keep the current weak, per-native-window focus request. A find bar or native sheet releases only its window's request. Closing it requests the currently selected slot only if the initiating window still exists, the slot still belongs there, its surface is visible and ready, and no other native editor has focus. `restoreFocus` never calls `makeKeyAndOrderFront`. Window activation changes native ordering but does not move another window's surface. Existing `PressID`, stage, remapping, repeat, and native-field precedence remain. Cmd+Shift+J retains its app priority.

`EmbeddedSurface` continues to borrow CEF's compositor and WebContents views. All cards for a slot use the same surface; no card can request a surface for another window's slot. Browser retirement still restores borrowed views before close. Parking a browser for a transfer needs a distinct engine operation: detach and hide its surface while retaining the host's never-key guard. Do not copy the probe's experimental early `returnViews` parking as final code. The final close returns views once and waits for `OnBeforeClose`, then host destruction, auxiliary widgets, and runtime shutdown.

## Downloads retain the original browser and context

At `can_download` or the first callback, the adapter captures the browser record, context token, current download settings, initiating window, and URL. Initial updates are allowed before the destination callback. The adapter creates one transfer record keyed internally by browser incarnation plus CEF download ID, and publishes one `TransferID`. No later lookup goes through `PageID`, `Session.loaded`, or the tab's current profile.

A decision callback and a progress/control callback are different resources. Copy item values inside each callback; never retain the borrowed item. An incoming callback reference is either transferred into a one-shot Swift owner or released on every branch, including missing owner, terminal state, and rejection. Replacing a retained update callback releases the old one. Callback methods and releases run on the appropriate CEF thread. Outgoing newly allocated callback references transfer to CEF; returned registration/context references belong to the adapter. The failed first probe demonstrates why these directions must not share an indiscriminate “release after call” helper.

Before showing a destination sheet, freeze the settings and reserve the operation. `NSSavePanel.beginSheetModal` belongs to BrkApp's initiating NSWindow, not `NSApp.keyWindow` at reply time or the CEF host. Queue one sheet per window. Closing a source tab with a pending decision cancels that undecided transfer. Closing the native owner dismisses its sheet and cancels; it never silently falls back to the default profile or another window. On every reply, check the operation is still awaiting that decision, its context has not begun disposal, and the application is running. Duplicate and stale replies are discarded; the borrowed callback has one final resolution.

After a destination is accepted, a public source-tab close, source-window close, or profile reassignment removes presentation demand but retains the exact original browser/context until transfer termination. A replacement browser may exist for the same slot with a new generation. It cannot receive old page observations; transfer updates go through their separate channel. Destination settings remain the captured values. Multiple transfers hold one browser until all finish, cancel, or fail.

Profile deletion first refuses new operations for that context, cancels decisions and active transfers, waits for terminal cleanup and browser closure, releases the context, then uses the existing next-launch directory-deletion marker. Domain state records deletion-in-progress until disposal reports completion. Failure keeps a recoverable tombstone; it cannot pretend data disappeared. Last-private-window closure follows the same cancel/drain order and invalidates that private-session ID immediately. A newly opened private window receives a new session ID; the old drain cannot affect it. Public download files can remain after completion; private metadata never enters `Doc` or diagnostics in product builds.

User cancellation publishes `cancelling`, invokes the retained CEF callback, and awaits the terminal update. Preserve cancelled, interrupted, and completed as different outcomes. If completion won the race before cancel was accepted, report the completed file. Once a terminal result is accepted, subsequent duplicates cannot revive the row. Never delete a completed file because a late cancel arrived. Remove only the operation's reserved staging/partial output; never guess a neighboring `.crdownload` belongs to it. A cleanup failure reports the retained path. Browser crash without a terminal transfer update reports failure/unknown file disposition after bounded inspection, not successful cancellation.

Quit stops new work, cancels transfers and native sheets, and gives terminal callbacks a bounded drain interval. Then run the existing ordered browser/host/runtime teardown. A missing terminal callback or unclosed browser produces an explicit nonclean result. Relaunch marks unfinished persistent transfer records failed; it does not claim automatic resumption. No state-file write happens from the CEF callback bridge.

## Find is a document operation

Opening the bar creates window-local state; editing text creates a fresh operation. An empty query stops finding and clears highlights. Initial search, next, and previous are distinct actions. For this pinned runtime, initial search stops the prior session then requests a match with `findNext = true`; false counts/highlights but the probe returned ordinal zero. Results carry the search token and document token, plus count, optional active ordinal, and final-update status. Zero/no active match is displayed as no selection, not a fabricated ordinal of one.

CEF does not accept our operation ID in `find`. Its native identifier is allocated inside Chromium and is process-wide, so predicting `last + 1` per browser is wrong. The adapter owns correlation. It stops the previous session before a replacement query and serializes next/previous steps until the prior step's final callback. It maps the new native search to the pending domain operation on the same main-thread call path. Unknown/stale IDs are ignored. Do not enqueue raw find callbacks onto a later task and then stamp them with whatever query is current.

For the pinned runtime, CEF routes results through Chromium's session filtering before forwarding them. The helper rejects aborted/older sessions; CEF can also emit its reset result after a stop. Ignore reset identifiers and do not turn them into a new search. These are pinned-source observations, supported by the rapid-replacement probe, not a portable promise for any CEF version. Re-run the sequence on runtime upgrade. See [CEF result forwarding](https://raw.githubusercontent.com/chromiumembedded/cef/14c5a08/libcef/browser/browser_host_base.cc) and [Chromium session filtering](https://raw.githubusercontent.com/chromium/chromium/154.0.8037.98/components/find_in_page/find_tab_helper.cc).

On main-frame `on_load_start`, synchronously stop the old find session and advance document identity. Same-document fragment/history changes do not mint a new document. Provisional navigation fences new UI answers while loading; failure can restore the prior document only with its original token. Renderer death invalidates the document even if the browser survives. Count events for an older document never reach the bar. The 50,000-match race probe issued replacement and stop before old results returned, then navigated and searched again in the same browser. It emitted several final and nonfinal updates for the new identifier before settling at one match. Therefore `finalUpdate` completes a pass, not the lifetime of the search: keep the search session until stop, replacement, or document invalidation. Gate searches during navigation and preserve query/document identity across every later update.

Use Selection to Find reads the focused frame and element selection through a renderer-side adapter and returns text with a document/frame token. Jump to Selection uses that same still-valid range and scrolls/focuses it. It is not “jump to the last find rectangle.” Replace is limited to enabled text inputs, textareas, and contenteditable selections. The renderer checks document, frame, focused editable element, selection revision, read-only/password exclusions, and range immediately before mutation; emits normal input events and preserves undo as supported. It returns replaced count or unsupported/stale. Plain document text, cross-origin frame selection access, IME composition, and editor-specific undo are not solved by `executeJavaScript` or a CEF find count. This bridge and its native tests are a named implementation dependency; A039 remains incomplete until they work.

## Save, PDF, and print complete with observable outcomes

Save Page supports MHTML through `Page.captureSnapshot` on the actual browser. The CEF DevTools observer owns a registration until operation completion or browser closure. Map each message ID to an operation/document; parse responses inside the adapter. Write into an operation-owned staging file, validate bytes, and atomically commit to the user-chosen destination. An accepted command or a visible save dialog is not completion. Link/bookmark export remains the existing separate `ExportDocument` workflow.

PDF uses CEF `print_to_pdf` with a completion callback and a staging destination. Validate the callback, PDF signature/page structure, and final filesystem write before reporting saved. Cancellation does not have a corresponding raw CEF PDF cancel call. Mark the operation cancelling, suppress publication, retain the browser until callback or bounded failure, then delete the staging file. If cleanup cannot be confirmed, return failure with the retained staging path. Navigation invalidates the pending output; do not export the next document accidentally. Repeated operation IDs cannot start duplicate exports.

For printing, render a PDF snapshot first, then present an AppKit/PDFKit print sheet on the initiating Brk window. The native adapter owns the `NSPrintOperation`, reports cancellation or submission to the OS spooler, and removes the PDF when the native operation finishes. It must never label a dialog-opening event or spooler submission as paper successfully printed. Do not rely on hidden-toolbar Chrome print preview for product UI. The evidence report records native command behavior; The PDFKit probe opened a sheet on the Brk window, invoked its Cancel button, received `submitted = false`, and quit cleanly. Actual printer submission and owner-close races remain acceptance gates.

All UI phases have an operation ID and weak native owner. Closing the owner cancels its sheet. Output engine work cannot transfer to another window because it happens to be key. For an already selected destination, source close cancels document output and drains its callback using a retained browser. Unlike public downloads, no new document snapshot is started after source removal.

## Data removal is not context disposal

Quick Clear Cookies targets all cookies whose host/domain scope matches the displayed host, including applicable domain cookies. The raw URL-only API is narrower, so implementation must enumerate matching cookies and delete the intended host/domain/path tuples through a tested method. Until that method passes origin/profile tests, the menu stays unsupported rather than silently clearing fewer cookies. A whole-context cookie wipe uses the documented empty-URL form with a completion callback.

HTTP-cache clearing is context-wide. The confirmation names that scope; an origin-only HTTP-cache request is rejected. Cache completion must arrive before a dependent reload. Reload additionally checks the captured document and context tokens, so switching tabs, navigation, profile reassignment, or window closure cannot reload the wrong page.

History is the Brk visit ledger and is removed by the reducer. It never calls context disposal. Full browsing-data requests validate every scope/class combination before mutation. Passwords are unsupported in this batch. LocalStorage, IndexedDB, service workers, and Cache Storage require a measured per-origin storage path and explicit result. A missing implementation returns `unsupported` and performs no partial best-effort deletion. Runtime failures after valid multi-class execution return completed classes and failed classes, with no automatic reload. Once irreversible deletion has begun, cancellation is “too late” and completion remains observable; only queued operations can cancel without changes.

Serialize overlapping deletion operations by context; queue new writes/navigation if the product promises a lasting empty state, or clearly define removal as a point-in-time operation. Profile settings and Favorites survive clear-data. Profile deletion and private expiry instead use `dispose`, whose lifetime barrier includes retained operations and request-context readiness callbacks.
