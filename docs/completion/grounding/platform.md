# Platform grounding for the remaining Brk work

This report describes commit `6d2d6d50694b17d0c5e4ffcaf5b69bff4a30011d`. It owns A036–A055, A083–A088, A093–A098, and A102–A112, exactly 43 rows. The companion proposal is [platform.json](../proposals/platform.json). It is an input to the parent's explanation and two interface sketches, not a selected architecture or implementation plan for the entire product.

Brk already embeds real Chromium pages, separates profile request contexts, presents downloads and history, and hosts several native window kinds. The largest immediate defects are at the lifetime boundaries. Download cancellation changes only a saved row. Download updates depend on the originating page still being loaded in its current profile. Clear Browsing Data invokes the profile-deletion path. Find results, printing, site controls, permissions, extensions, and media still need product contracts and engine integration.

The agreed remaining inventory stays in scope. Account, membership, referral, and Send to Dia are excluded by the recorded user decision. Sharing means local file export. AI uses local Claude or Codex command-line tools. The updater is deferred. None of those decisions excuses a missing row in this report. Production code, the canonical inventory, and the canonical audit are unchanged.

## Flow

### Page actions and focus

1. `MainMenu` or a command-bar result resolves an `ActionID.spec.command`. Native menu choices call `KeyRouter.menuAction`. CEF keyboard callbacks call `ChromePage.browser(handleKeyEvent:)`, then `CEFEngine.pageKey`, then `KeyRouter.engine(page:key:stage:pressID:)`.
2. `AppStore.dispatch` or `dispatchKey` calls `reduce`. `Rules/Tabs.swift:90` resolves `.focused` to a loaded page, including a Peek's page, and emits `Effect.page(PageID, PageAction)`.
3. `AppStore.publish` reconciles `snapshot.pages` before rendering. `AppStore.run` then calls `engine.perform`. `CEFEngine.perform` maps back, forward, reload, stop, fixed-step zoom, DevTools toggle, and crash recovery to CefKit.
4. `BrowserClient` invokes `ChromePage`. `CEFEngine.pageDidEmit` accepts events only while running and while `live[page.id] === page`. `KeyRouter` dispatches a `SystemEvent.page` to the reducer. `Rules/Tabs.pageEvent` adds a second gate requiring a loaded, existing tab.
5. The current focus contract is `engine.focus(page, in: window)`. Requests belong to native windows, not one global focused-page variable. `WindowController.windowDidUpdate` repairs only a visible window with no native responder. `CEFEngine.restoreFocus` checks current page object, window identity, attachment, visibility, and input readiness. A late callback cannot take focus from a native editor or from a surface that moved to another window.

Copy URL bypasses CEF: `Rules/Tabs.pages` formats the stored URL/title as plain text, Markdown, or quote text, and `AppStore.run` writes the pasteboard. Share exports a link document through `Rules/Sidebar.exportDocument` and `ShareExport.run`; it does not save the page contents. Standard Edit commands mostly use AppKit responder selectors. The existing CefBrowser editing methods are used by CefSwift's OSR host, not by a Brk editing adapter.

### Download decision, progress, cancellation, and persistence

1. `BrowserClient.on_before_download` snapshots `CefDownload`, releases the raw item, and asks `ChromePage.decidePolicyForDownload`. `can_download` currently returns true.
2. `ChromePage` asks `KeyRouter` for a `DownloadDecision` using only the logical page ID. `KeyRouter` looks up the page in the current snapshot, then uses that profile's download settings. A missing page falls back to the default profile. Incognito deliberately uses the default profile's download destination settings.
3. `.save` chooses an unused filename in the directory. `.ask` runs a modal `NSSavePanel`. `DownloadFiles.reserved` avoids collisions between current downloads. `ChromePage.destinations[cefDownloadID]` retains the destination, emits `.started`, then returns `.allow(destination:)`. CefKit calls the before-download callback's `cont(path, show_dialog: 0)`.
4. `BrowserClient.on_download_updated` releases `cef_download_item_callback_t` immediately, discarding `cancel`, `pause`, and `resume`. It forwards a value snapshot only. `CefDownload` merges interrupted and cancelled into `isCanceled` and omits interruption reason, validity, and in-progress state.
5. `ChromePage` drops updates received before it has a destination. Completion removes the reservation; interruption/cancellation becomes `.failed`; other updates become `.progress`. It emits through the live-page gate.
6. `Rules/Library.downloadEvent` derives the profile again from the current tab. Starts create `Download(id, url, filename, path, received, total, state, startedAt, profile)`. Later events require the row ID and this newly derived profile to match. Incognito events never enter the persisted ledger. `StateCodec` restores unfinished rows as failed.
7. The Library cancel button dispatches `.cancelDownload(id)`. The reducer changes the row to cancelled without an effect. A later finish changes it back to finished. The probe executes this exact sequence. Existing `LibrarySpecTests.test_downloadEventsFollowTheEngineAndTheUsersCancel` explicitly tests that behavior; it is not a network-cancellation test.

Two independent gates lose legitimate download updates after tab closure: `CEFEngine.pageDidEmit` rejects the retired ChromePage, and `Rules/Tabs.pageEvent` rejects unloaded tabs. Profile reassignment also changes the context used by the reducer, so the original row cannot receive its completion. The synthetic probe confirms the reducer part even when an event bypasses the engine gate. Whether CEF actually continues a transfer after the originating browser is destroyed remains untested. Retaining a cancel handle alone does not answer that question.

The decision callback has the opposite problem. `ChromePage.decidePolicyForDownload` calls the delegate directly without the engine's live-incarnation/phase check. A late callback from an old incarnation can consult a new profile or the default profile, reserve a path, and allow a download whose start event is then dropped. The modal save panel also permits reentrancy before the destination is accepted. This is a source-proven unchecked path, not a reproduced native race. The next contract must freeze the initiating context and revalidate an asynchronous answer.

Reservations are removed only on complete/cancelled snapshots. There is no close-time destination cleanup. If no terminal update arrives, the reservation can remain until process exit. A download operation must either outlive its page with a documented context lifetime, or reach a truthful terminal state when that lifetime ends. Downloads must not become admissible stale page events just to bypass the current guard.

### Request contexts and site-data work

`project` derives `BrowsingContext` from the tab's container. Default pages use the runtime's `Chromium/Default` cache. Each custom profile has `Chromium/Profile-<id>`. Incognito windows share one in-memory request context until the last incognito window closes.

Custom contexts wait for `ProfileLoader.on_request_context_initialized`. Its weak owner and cancelled `onReady` closure prevent a forgotten loader from replaying demand. `CEFEngine.reconcile` retires the old page when the same PageID asks for a different context, then creates a new incarnation. The previous page can remain in `closing` or `destroying` until CEF finishes.

`forget(.incognito)` releases the engine's context reference. `forget(.profile(id))` releases its loader/context and marks its directory for deletion before CEF starts next time. `forget(.profile(.default))` does nothing. This contract exists for private-session disposal and deleting an unused profile.

History's confirmed Clear Browsing Data currently deletes the profile's Brk history and emits `forgetBrowsingData(profile)`. For the default profile, site data remains. For a custom profile, live browsers still hold their context, and the directory is marked for wholesale deletion on next launch even though the profile record still exists. This does not implement clearing selected live browsing data. The domain test checks the emitted effect; it never checks cookies or storage after clearing. A042's separate Clear Cookies/Cache and Refresh menu actions are disabled.

### New pages, native windows, and external links

`on_before_popup` provides `CefWindowOpenRequest`. Brk returns `.handled`, cancels CEF's popup creation, and converts the request into a domain tab. `.popup` and foreground requests both become foreground tabs. This loses feature-sized popup windows, opener scripting, and meaningful empty-URL popup behavior. A null target is swallowed. `on_open_urlfrom_tab` discards disposition and user gesture in CefKit; Brk assumes background tab, so Cmd+Shift+click is not faithfully represented.

The domain resolves scratch openers to their owning window even when hidden. Incognito modifier opens remain in that window's private container. Preserve these rules and W2-P1/P1C/P2/P2C. Public Shift+click can open a scratch Peek; Option+Cmd can open Little Brk. Pinned/Favorites navigation uses `KeyRouter.shouldNavigateTo` and a short registrable-domain heuristic. The wrapper currently discards `frame`, so the comment promising a main-frame-only hook is stronger than the actual adapter.

`Rules/Windows` owns `.standard`, `.incognito`, and `.little`. There is no blank-window kind or stay-on-top state. A Little Brk is an NSPanel with no sidebar and an Open In menu, but `isFloatingPanel = false`. Open In offers spaces, not folders. It creates a new tab ID from stored Tab data, so it recreates a browser rather than preserving live page history, form state, or a download's page identity.

Several standard windows share the sidebar. `CEFEngine` provides one NSView per PageID, while window selections are per-window. Selecting the same logical tab in two windows needs an explicit ownership result: a single NSView cannot be attached twice. The current W2-4 assertions exercise independent loaded pages, not simultaneous presentation of one PageID. Do not infer that the latest per-window focus repair resolves this separate ownership question.

Little Brk auto-archive runs on clock ticks using `lastActiveAt`, not activity or key-window events. Merely typing, watching media, or remaining key does not refresh this timestamp. The unit test proves the timer, not the word "idle" in the feature's full behavior.

`GetURLHandler` converts macOS GetURL into `SystemEvent.externalURL`; ordered Air Traffic Control host patterns choose a space or Little Brk. `DefaultBrowser.register` requests http and https registration. The settings view does not consume `isDefault`. W2-7 calls a control-protocol `externalURL` helper, so its title does not establish real Launch Services delivery or user confirmation.

### Keyboard shortcut detail

The raw header instructs clients that plan to handle a shortcut in `on_key_event` to set `is_keyboard_shortcut = 1` and return false in `on_pre_key_event`. `BrowserClient.swift:750` ignores that out-parameter. The delegate's Bool cannot express "pass to renderer, but expect an app shortcut afterward" separately from ordinary pass-through. `PressCorrelator` can pair callbacks that arrive; it cannot create a missing post callback.

There are also Chrome's native accelerators. The pinned `cef_browser_view_capi.h:85` documents `set_prefer_accelerators`: true can run a normal-priority accelerator before web content or the keyboard handler, false gives them first chance. Brk/CefKit does not call it, so the documented default applies. `on_chrome_command` is another potential interception point, not currently registered. These are distinct mechanisms and neither is a proven fix for every shortcut after the views move.

Keep the current Downloads default: `Actions.swift:390` sets Cmd+Shift+J to `.app`, and `KeyRoutingSpecTests.testDownloadsOpenBeforeChromiumCanConsumeItsOwnDownloadShortcut` plus W2-11 verify it. A user override to `.page` still passes to the page. Compare interface alternatives for the extra shortcut intent only after logging pre/page/post/Chrome-command sequences. Test preventDefault, editable inputs, repeat, two rapid presses, menu ordering, native fields, and multiple windows. Do not change the default as a side effect of wrapping the out-parameter.

## Boundaries and invariants

| Boundary | Current invariant to preserve | Gap for the next design |
| --- | --- | --- |
| UI to domain | Only reducer writes state; app effects handle native I/O; no CEF pointers in commands. | Find/result state, download commands, data-clear operations and asynchronous failures need explicit vocabulary. |
| Page identity | Retired generations cannot update a replacement or steal focus. | A PageID alone is insufficient for modal answers, search results, and old-context download decisions. Navigation within the same incarnation also invalidates some answers. |
| Download lifetime | Persistent records retain original profile; private files may remain but private metadata is omitted. | Control handles and ownership must not require a currently shown/live tab or re-derive context from its new profile. No fake terminal cancellation. |
| Context disposal | Delete custom profile directories only before CEF owns them; dispose private context after last private window. | Separate clear-data, profile deletion, and private-session expiry. Decide what happens to active operations before releasing context ownership. |
| Permission callback | CEF callback must resolve/release according to its contract on the UI thread. | Preserve prompt identity, origin, frame, mask, context, incarnation and dismissal. Navigation or close must not grant a stale origin. Handle owner-missing callback references explicitly; the current success closures alone release them. |
| View lifetime | Restore borrowed views before browser close; wait for browser close; dispose auxiliary widgets before runtime shutdown. | All new dialogs, DevTools windows, extension popups, print UI and PiP must obey the same order and have identifiable owners. |
| Focus | `focus(page, in: window)` never activates another window, and native editors keep focus. | A new find bar/prompt must cancel only that window's page intent and restore it only if still applicable. |
| Privacy | Private popups resolve by scratch owner, not current visibility; no private history/archive/download entries in persisted state. | Existing tests cover saved records and cookies, not all on-disk/OS logs. ChromePage logs title and download path with `.public`; broader "no saved data" claims require a separate log/storage audit. |

The hidden host is not Chrome's usable browser shell. `ChromePage` sets `showsChromeToolbar = false`; `HostWindows.adopt` makes the CEF host click-through and never key. The compositor and web-content views move, while Chrome's internal view/window ownership remains. A command that returns enabled or opens a Chrome widget may still present unusable, misplaced, or untracked UI. Existing download shutdown fixes specifically demonstrate why an auxiliary widget needs lifecycle coverage. ## Non-obvious things

- A failed or interrupted download currently becomes `.failed`; the wrapper erases the reason and the distinction from cancellation. The next implementation must first preserve raw state, then decide what the UI calls it.
- `on_download_updated` may precede `on_before_download` according to the pinned header. A control registry cannot assume the start event always arrives first.
- A profile change preserves a logical PageID while replacing its browser. Open In instead creates a fresh tab ID. Both break page-owned download assumptions in different ways.
- `reload(ignoreCache: true)` bypasses cache for navigation; it is not deletion of cookies, HTTP cache, or site storage.
- The parent native logs contain Chromium "Encryption is not available" diagnostics even though scenario assertions pass. Those scenarios do not establish encrypted credential storage.
- `cef_request_context_t.clear_http_cache` is gated by `CEF_API_ADDED(14400)`, which is available at the pinned 14800 ABI. Settings observers are available from 13401. Experimental declarations must not be treated as available just because they appear in a 154 header file.
- Cookie deletion with a URL and no cookie name deletes host cookies, not domain cookies. A per-site operation needs a stated host/domain scope and a completion barrier before reload.
- CefKit's `find` wrapper is insufficient for next/previous and result UI. Raw CEF supplies a callback identifier; Brk still needs to prove how that sequence correlates with its own searches after close, navigation, or context replacement.
- The ordinary permission callback is not a deferred prompt. Default `.deny` resolves it immediately. The wrapper also maps desktop capture to camera/microphone, so a native prompt would otherwise describe the wrong capability.
- `BrowserClient` releases the `frame` argument before navigation policy. A comment saying "main frame" does not enforce it. Similar loss occurs for new-tab disposition and permission prompt identity.
- Settings-only implementations include website appearance, automatic PiP, sound effects, and restore-windows-on-launch. The last has no restore-path consumer even though ordinary session restoration works.
- Native Edit menu construction and `.later` menu availability are different from webpage responder behavior. All disabled small actions remain explicitly listed in the JSON, including replace/jump, source/console/network/Apple Events/developer mode, blank window, Peek Email, save/print/cast, and extension installation/management.

## Bounded proposal for the next implementation batch

The next batch should close **download control/ownership and essential page-operation contracts**. It should not promise to finish all 43 rows at once. The full inventory remains scheduled after that batch. The parent should compare two interface sketches against the following required behavior before selecting shared APIs.

1. Make cancellation reach CEF, preserve interrupted/cancelled/complete state, and report a terminal result that matches the file and transfer. Freeze originating context and incarnation at download start. Decide and test what happens after source tab close, profile reassignment/deletion, last private-window close, save-panel cancellation, and immediate quit. Keep duplicate-name handling and private metadata omission. The ownership decision must be based on a retained-callback/native-lifetime experiment, not on the existence of `cancel()`.
2. Add native find UI with initial/next/previous/close, count and ordinal updates, and stale-query handling. Explicitly retain Find and Replace, Use Selection, and Jump to Selection in the acceptance list; resolve editable-only behavior and selection retrieval before claiming A039 complete. Close/navigation/context replacement and per-window native focus are first-class acceptance cases.
3. Provide a local save/print/PDF path with explicit operation identity, destination, completion/error, and host-window ownership. Run a small CEF feasibility check for `print_to_pdf` and page-save commands before deciding whether native Chrome UI is usable. Local link export stays separate from a saved offline page. Cast remains in the inventory with its own receiver/route validation.
4. Separate profile deletion/private disposal from live data clearing while defining the engine interfaces. Wire cookie/cache clear-and-refresh only after scope and completion are explicit. Broader storage removal and per-profile privacy controls remain A095 until their own origin-isolation tests pass. Preserve unrelated profile data and never claim clearing from a released pointer alone.

Required acceptance for this batch includes a throttled loopback download with byte/file observation after cancel, late callback ordering, two profiles with the same URL, close/reopen of the same PageID, private navigation regressions, and immediate shutdown with all new native UI types. Run focused unit tests, the signed build, and affected CEF scenarios. Reuse N1/N2, W2-11/Q/A/P, W2-P1/P1C/P2/P2C and W2-2/3/4; add the missing cases rather than weakening existing assertions. Leave Cmd+Shift+J's app priority unchanged.

The architect pair should compare concrete ownership alternatives for operations that survive pages and callbacks that belong to a particular document. It should return type shapes, callback retention/release points, error/terminal states, and stub/real-engine conformance before implementation. This report intentionally does not select a manager type, registry layout, host-retention strategy, or command transport.

## Open questions

1. Does a retained CEF download control callback remain usable after its browser and native host are destroyed? Does the transfer continue when that was the last browser in the request context? Test on the pinned runtime before choosing ownership.
2. How should source closure, profile deletion, and private-session expiry affect active downloads and unfinished files? Existing code supplies no truthful operation contract.
3. Does `is_keyboard_shortcut` plus the documented default accelerator preference produce the expected callback order on the reparented Chrome view for each relevant chord? Does `on_chrome_command` need integration? No native probe was run here.
4. Which save/print dialog and PDF paths work without Chrome's toolbar or key host window? Who owns their windows and callback cancellation during teardown?
5. Which raw/CDP path can remove localStorage, IndexedDB, service workers and cache storage with the intended profile/origin scope? Cookie and HTTP-cache declarations do not answer that.
6. Can this pinned Chrome runtime install a harmless unpacked extension, retain it per profile, expose its action popup, and open shortcut settings after embedding? Store installation additionally depends on its live distribution flow. No old extension API or wrapper comment answers those questions.
7. What OS permission metadata and signing configuration must app and helper bundles carry, and what callback sequence occurs when macOS denies camera/mic/screen/location access? Native prompts must preserve origin/frame/private ownership.
8. Can media capture/PiP operate with user activation and hidden tabs without unwanted auxiliary windows or cross-profile state? How does Meet's document PiP differ from a single video element?
9. What is the intended ownership when two standard windows select the same tab? What does authenticated Arc show for floating Little Brk, idle expiry, find-and-replace in a page, and full history? These are unverified product details, not reasons to remove the rows.
