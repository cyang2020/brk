# AI 对话列表

## 背景

2026-11-09，用户看了改过的对话面板后问："这里的ui是不是还少 我们哪里能看到所有的ai对话threads啊"。

当时的情况是这样：
- 每个对话是一行 tab，放在开始它的那个 Space 的侧边栏里，点 × 就归档。
- 命令栏只能按标题搜到对话。
- 没有任何一处能一次看到所有对话。
- 别的 Space 里的 agent 停下来等批准时，你在当前 Space 看不到，它就一直停着。

我先提了两处入口：面板里的对话列表，用来边看网页边切对话；Library 里新加一页"AI 对话"，用来管理。用户接着说："我觉得可以和 space的切换一样 右边的panel和左边一样 可以横滑到 threads"，又问："每个space的ai对话是否是一样的 意思是 每个space下面都有个对话列表？"。我建议每个 Space 一个列表，用户回复："好 继续吧 就按这么做"。

## 面板横滑到对话列表

面板分两页：对话列表和当前对话。指针在面板上时两指横滑，就在这两页之间切换。这和指针在侧边栏上时横滑换 Space 是同一个手势，跟手的方式和松手后的弹回动画也一样。列表放在前一页，就像侧边栏里 Library 排在第一个 Space 前面。

面板底部有两个小点表示现在在哪一页，样子和侧边栏底部的 Space 圆点一样。标题栏有一个列表图标，用鼠标、没有触控板的人点它也能到列表。

不做成一个对话滑到下一个对话，有两个原因：对话一多要连滑很多下；对话也不像 Space 那样有用户自己排好的顺序，滑到下一个是哪个说不清楚。

面板里画出的页面如果本身能横着滚，比如很宽的表格，指针在页面上时横滑先滚页面。这和网页卡片现在的做法一样。

设计稿是 `docs/design/ai-threads-mockup.html`。上半部分的第一行是侧边栏现有的横滑顺序（Library、购物、工作），第二行是面板照着排出的两页（购物的对话列表、当前对话），有粗框的那一页是正在看的。下半部分是下一节说的每个 Space 一个列表。

## 每个 Space 一个对话列表

每个 Space 的面板只列这个 Space 的对话，理由有三个：
- Space 就是用户用来分开"工作""购物"这类事情的地方，对话的 tab 行本来也放在开始它的那个 Space 里。如果每个 Space 都列出全部对话，购物的对话会出现在工作 Space 里，Space 的区分就没有用了。
- 不同 Space 可以用不同的 profile，也就是不同的登录身份，而 agent 本来只能看到自己 profile 的 tab。把所有对话混在一个列表里，两个 profile 的东西就会出现在一起。
- 每个 Space 本来就记得自己上次看的 tab。面板也照这样，记住每个 Space 上次看的是哪个对话、停在列表页还是对话页。

所以左边换 Space 时，右边面板跟着换成那个 Space 的列表，并回到你在那个 Space 上次看的对话。

列表里有这些：
- 最上面一个搜索框，搜这个 Space 里对话的标题和全文。要搜所有 Space，去 Library。
- 对话按"等你处理""进行中""今天""昨天""更早"分组。"等你处理"有两种对话：在等你批准的，和回复了你还没看的。只要回复出来之后这个对话在面板或 tab 里显示过，这条回复就算看过了。
- 每行两行字：第一行是对话的名字，第二行是它现在的状态，比如"想运行一条命令""2 分钟前回复了""读到第 5 个 tab""11:32 · 1 个 AI 页面"。在等批准的，行右边是一个 Space 主色的"等你确认"小条；有新回复的，是一个小圆点；正在跑的，是转圈。
- 已归档的对话也列出来，用灰字，第二行写"已归档"。点一下就恢复，可以接着聊。（第 8 步去掉了：对话没有侧边栏那一行，也就没有归档和恢复，旧的对话按时间沉到"更早"。）
- 在列表页的输入框里打字，就在这个 Space 里开一个新对话。
- 点一行，在面板里打开这个对话。右键菜单有：在 tab 里打开、重命名、归档或恢复、移到别的 Space…、彻底删除…。彻底删除会先问。（第 8 步改了：右键菜单只剩重命名、移到别的 Space、彻底删除…。）
- 对话要换 Space，可以把它那一行 tab 拖到别的 Space，也可以用右键菜单。换过去之后，两个 Space 的列表都会跟着变。（第 8 步改了：没有那一行 tab 了，改成把列表里的一行拖到侧边栏底部的 Space 圆点上。）

## 别的 Space 有对话在等你

只按 Space 分开列表，代价是别的 Space 里发生的事你看不到。下面三处提示补上这一点，它们都只看同一个 profile 里的 Space：
- 别的 Space 里"等你处理"的对话，会以小条的样子显示在当前列表最上面。小条上有那个 Space 的颜色圆点、Space 名和对话名，点一下就切到那个 Space 并打开这个对话。别的 Space 里的其他对话不显示。
- 侧边栏底部的 Space 圆点里，有对话在等你的那个 Space，圆点外加一圈它自己的颜色。处理完以后这一圈就消失。
- 面板标题栏的列表图标上显示一个数字，是这个 profile 里所有"等你处理"的对话数。

Brk 不在最前面时，agent 一等批准，Brk 就发一条 macOS 通知。跑了一分钟以上的回复完成时，也发一条。点通知会回到 Brk，并打开那个对话。

## Library 里的"AI 对话"页

这一页列出这个 profile 所有 Space 的对话。排法照 Library 里现有的"已归档 tab"那页：
- 左边的图标列里，在"已归档"后面加一个"AI 对话"。
- 中间一列，最上面是全文搜索框和"筛选"，筛选能按 Space、agent、状态、有没有 AI 页面来选。下面有"全部""等你处理 N""有 AI 页面"三个快捷选项。对话按时间分组，每行写 Space 圆点和名字、agent、时间或状态。
- 右边显示选中对话的全文，和它画过的页面。下面是四个按钮：继续这个对话（切到它的 Space，在面板里打开）、在 tab 里打开、移到别的 Space…、彻底删除…。（第 8 步去掉了"在 tab 里打开"，剩三个按钮；筛选里的状态也不再有"已归档"。）

设计稿是 `docs/design/ai-threads-library-mockup.html`。稿子里的颜色和图标是示意，实现时照 Library 现有的样子和 Space 主题来画。

命令栏也改成能搜对话全文，不只搜标题，和 Library 用同一套搜索。结果里写出对话在哪个 Space。

## 不能坏的东西

- 对话仍然是侧边栏里的 tab 行。置顶、改名、放进文件夹、点 × 归档、自动归档、从归档恢复，这些都照旧。（第 8 步改了：对话不再是侧边栏里的 tab 行，只在右边面板里。）
- 会自己更新的 AI 页面照常更新，打勾和笔记照常保存。
- 指针在侧边栏上横滑换 Space、在网页上横滑前进后退，都不受影响。
- 对话面板融进窗口那一版的所有行为都保留：停止、授权、@ 列表、拖 tab 进来、加号菜单、页面存成 tab。
- 无痕窗口里没有对话列表，也看不到别的窗口的对话。

## 验收

用真实启动的 Brk 和真实的输入事件来验，横滑要用真的触控板滑动事件，不能在程序内部直接切页。下面每一项都要验：
- 在面板上横滑到列表再滑回来；点列表图标也能到列表。
- 左边换 Space 时，面板换成那个 Space 的列表，并回到上次看的对话。
- 在 A Space 时，B Space 里的对话开始等批准：A 的列表顶上出现小条，B 的圆点出现一圈颜色，列表图标上的数字加一。点小条会切到 B 并显示授权框。批准后，这一圈和这个数字都消失。
- 已归档的对话出现在列表里，点一下就恢复。
- Library 的"AI 对话"页能搜到只出现在对话正文里的一个词，能按 Space 筛选，能彻底删除。
- 命令栏能按正文搜到对话。
- 用真实的 Claude 在两个 Space 各开一个对话，把上面的流程走一遍。

截图放在 `verify/ai-native/threads/`，浅色和深色 Space 各一套，每套包括列表页、顶上的小条、带圈的 Space 圆点和 Library 页，和设计稿并排比较。另外照例跑完整的单元测试、AI 相关的真实场景，以及和 main 在同一块屏幕上的截图对比。

## 实现时补的决定

做的时候有些地方上面的规则和设计稿没写到，下面是当时怎么定的，都可以改。

**对话属于哪个 Space。**（第 8 步改了：对话自己记住属于哪个 Space，在哪里开始的就属于哪里，移过以后属于新的 Space；下面这段只在更新后第一次启动、把旧的对话行拿掉时用一次。）对话的 tab 行在哪个 Space 的置顶或今天里（包括其中的文件夹），对话就属于哪个 Space。行已经归档的，属于归档前所在的 Space。行在收藏里、或者没有行的，属于开始这个对话时的 Space。这个 Space 被删掉了，就算这个 profile 的第一个 Space。所以把对话的行拖到别的 Space，和用右键菜单移过去，结果一样。

**面板怎么开、怎么关。** 对话页没有对话时，面板只有列表一页，底部不显示小点，也滑不动。面板关着时，按 ⌥⌘A，或者在命令栏输入"AI 对话"，会打开面板并停在列表页；这个入口是合并时加的。问一个问题、拖 tab 进来、在 Library 里点"继续这个对话"、点通知，打开的是对话页，再往前滑就是列表。关闭按钮在两页上都是关掉整个面板。

**换 Space 时面板里的东西。** 已经保存的对话收起来，正在跑的回复在后台接着跑，回复完成后算"没看过"。还没说第一句话的新对话、Brk 自己的提示消息（比如"Max 没打开"）不跟着 Space 走，换 Space 就没有了。换到另一个 profile 的 Space 时也是这样，正在跑的回复不会被取消。这时 agent 的 tab 工具还是只看对话自己那个 profile 的 tab；窗口显示的是别的 profile 时，它不能打开、切换、关闭或移动 tab，会告诉 agent 先让用户回到原来的 Space。

**看过的判断。** 面板停在对话页显示这个对话（Library 打开时面板看不见，不算），或者它的 tab 显示在网页卡片里，或者在 Library 的"AI 对话"页选中它，都算看过。Brk 不在最前面时也按这条算。合并时确认保留这条：这时对话就显示在面板或 tab 里，回到 Brk 第一眼就能看到；要提醒的是没显示出来的对话。

**底部的小点。** 小点和侧边栏底部的 Space 圆点在同一条水平线上，那一行和侧边栏的 Space 圆点那一行一样高（50 点）。所以有列表的面板里，输入框的下沿比网页卡片的下沿高 40 点。F 原来定的是"输入框的下沿和网页卡片的下沿对齐"；两条规则只能保留一条，这里选了和左边对齐，可以改回去。合并时看过截图，保留和左边对齐：左右两栏的底部一样，看起来更整齐。点一个小点也会切到那一页。

**带圈的 Space 圆点。** 只给别的 Space 加圈，当前 Space 里等你处理的对话就在列表最上面那一组。圈的颜色是那个 Space 的主色，浅色主题下调到较深、深色主题下调亮，保证在侧边栏底色上看得清。带图标的 Space 也加圈，圈是圆角方形。

**通知。** 只在 Brk 不是最前面的 app 时发。第一次发的时候 macOS 会问一次能不能发通知，这是系统的询问，Brk 不会替用户回答。点通知会把 Brk 带到最前面，在最前面的那个普通窗口里打开对话。测试实例不发通知，只记下本来要发的，由测试去读、去"点"。

**文字的语言。** 列表自己的字（标题"购物 的对话"、分组名、搜索框和输入框的提示、空列表的话）看这个 profile 最近更新的五个对话：每个对话取它最近一条能看出语言的用户消息，五个里多数是什么语言就用什么语言，一样多时跟最近的那个；一个对话都没有时跟着系统语言。只看最近一个的话，一个用英文写的对话就会把整个中文列表变成英文，做的时候就遇到了。每一行第二行的状态、"等你确认"小条、右键菜单、删除确认，跟着那一行对话自己的语言。Library 左边"AI 对话"这一格的名字、"筛选"按钮也按列表的规则；英文时这一格叫"Conversations"，因为"AI Conversations"在这一格里放不下。

**搜索。** 列表、Library 和命令栏用同一个搜索：先找标题里有这串字的，再找说过的话里每个词都有的；不分大小写，不分重音。说过的话不再截短，命令栏原来只看对话前 6000 个字，现在看全文。命令栏结果的第二行先写 Space 名，再写找到的那段话。

**Library 页。** 多了第七个图标以后，左边一列按原来"均匀分开"的规则排，Arc 的六个图标之间从 100 点变成 83 点。还没选对话时，右边显示列表的第一个。右边的全文是只读的：页面能显示，但在这里打勾、写笔记不会保存。"筛选"里有 Space、agent、状态（等你确认、有新回复、进行中、已归档、其他）和"有 AI 页面"，最后是"清除筛选"。

**右键菜单。** "移到别的 Space"是一个子菜单，列出同一个 profile 的其他 Space，所以没有带"…"。Library 里的按钮还叫"移到别的 Space…"，点了弹出同样的菜单。只能移到同一个 profile 的 Space，因为 agent 只能看那个 profile 的 tab。"重命名"把那一行变成输入框，回车确定，Esc 取消。"彻底删除…"用窗口里的确认框（和删除 Easel 的一样），写出会删掉多少个页面。

**AI 给对话起名字。** 第一次回答之后，用基础功能的小模型（和 Name Tabs 同一个通道，要求按 JSON schema 回答）给对话起一个短名字，用对话的语言，最多 40 个字。名字写进对话的标题和侧边栏那一行的标题，所以面板标题栏、侧边栏、列表和 Library 都显示它。用的是 Name Tabs 的开关：关着就保留第一句话；当时关着、后来打开的，下一次回答之后再起名。每个对话只起一次。用户在列表里重命名过，或者在侧边栏给那一行改过名，就不再起名，起名的请求已经发出也不覆盖。没有 agent 也没有 key 时，小模型没有路可走，保留第一句话。

**加号菜单里的 agent 和模型。** "换 agent 和模型"点进去，列出 设置 → Max 里报告为可用的 agent，每个下面是它报告的模型，现在用的打勾；最上面一行回到加号菜单。还没有 agent 报告过时，这一行仍然打开 设置 → Max。选了以后只管这个对话之后的消息：同一个 agent 换模型，接着它自己的会话；换成别的 agent，开一个新会话，把这次对话的记录带在下一条消息前面。这个选择存在对话里，重启以后还在。"agent 设置…"照旧打开 设置 → Max。

**授权框的"查看命令 / 收起命令"。** 原来用 Space 主色，深色 Space 里在授权框的底色上看不清。现在用次要文字的灰色，所有 Space 一样。
