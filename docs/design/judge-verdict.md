## Recommended base: B

B gives a future maintainer fewer opportunities to bypass the state owner. Main holds an opaque value, renderers receive a display contract, inbound UI commands are derived from their parser schema, and a total handler table connects that vocabulary to the reducer. Its sidebar projection contains the root IDs needed to implement moves without reaching into the domain. Its native-view interface also concentrates more work behind `render` and `viewFor`. These choices let workers extend behavior without learning or rewriting the tree representation. A has useful details, but its mutable public model, broader APIs and incomplete renderer inputs would require more coordinated changes. Choose B's shape, then resolve the contract gaps below before parallel implementation. Neither package is a verified browser.

## Grafts

1. **Port A's domain-test checklist.** Use A's `src/domain/reduce.test.ts` as the starting inventory for B's domain tests, translated to B's commands and public projections. It explicitly names move-cycle rejection, split dissolution, late page events, archive exclusions, repeat sweeps, persistence round trips and layout behavior. B currently supplies architecture TODOs but no comparable domain-test inventory.
2. **Port named space icons and the richer theme vocabulary.** A's `src/domain/model.ts`, `src/domain/theme.ts` and `src/renderer/chrome/SpaceEditor.tsx` provide named icons and explicit texture/intensity choices. Adapt these into B's validated `src/shared/theme.ts` and `src/renderer/sidebar/SpaceDialog.tsx`; at minimum, restore the named-icon option required by the plan's emoji/icon picker.
3. **Port A's content-area archive placement.** A's `src/domain/layout.ts` and `src/main/window-host.ts` put the archive in the content card. Apply that placement to B's existing overlay renderer rather than adding another renderer bundle. B's full-window archive currently blocks the dock and sidebar (`src/renderer/overlay/OverlayApp.tsx`), which weakens the archive-page experience.

## Risks in the base

- **Domain privacy is not enforced yet.** A main-process file importing `../domain/tree` passes B's current typecheck. Implement the checks in `src/architecture.test.ts` and prove they reject a forbidden import; also make `MENU_ORDER` exhaustive and eliminate or check the duplicated archive-reason vocabulary.
- **Archive restore lacks its fallback context.** `restoreEntry` in `src/domain/ops/archive.ts:22` promises restoration into the dispatching window's current Today when the original space disappeared, but accepts only `Ctx`, which contains time and an ID generator. Pass an explicit `WindowId` or destination. Choosing the first window would invent policy absent from the contract.
- **Close-and-keep can conflict with normalization.** `src/domain/ops/tabs.ts` unloads a closed Pinned/Favorites tab, while `src/domain/normalize.ts` repicks active items from existing tabs and loads every visible tab. Specify an intentionally empty selection or another exclusion so closing the sole pinned tab does not immediately select and reload it. Also reconcile this behavior with the plan's wording that Cmd+W/hover × archives tabs.
- **Observe native focus and isolate closing generations.** `src/main/tab-runtime.ts` lists no page-focus event that updates the focused split pane. Clicking another native pane must update domain focus before Cmd+L, Cmd+W or Cmd+D resolves `focused`. Its event listeners must also reject observations from a retired webContents after the same item ID has been restored into a replacement view.
- **Shortcut suppression needs a precise physical-press rule.** `src/main/input.ts` and `src/shared/constants.ts` describe only a time window after the hook path. Define handling for menu-first delivery, window identity, repeat events and two rapid genuine presses, then test swallowed keys and toggles. The spike does not verify macOS delivery order.
- **Strengthen local type invariants.** `src/domain/model.ts` permits zero-pane splits, arbitrary split children and mismatched section/space combinations. Use bounded pane tuples and a discriminated section-root type where practical; retain `normalize` for relationships that require looking up other entities.
- **The persisted schema is still empty.** `StoredDocV1Schema = z.object({})` in `src/domain/codec.ts` does not establish the documented file shape or the claimed field-completeness checks. Define the versioned stored types/schema and migration order before freezing persistence work.
- **Projection revision and overlay lifetime need separate contracts.** `src/shared/view.ts` says equal `rev` means identical content, but `projectWindow` accepts a changing `now` independently of state revision (`src/domain/project.ts`). Clock-only changes must still refresh archive grouping. Separately, `src/renderer/overlay/CommandBar.tsx` refers to reopening via revision, but its props contain no opening identity; add one so a retained overlay resets its query on a new opening without resetting it on ordinary page-event updates.

## Convergence

Both candidates independently choose main-owned state, a pure reducer for page events and user actions, whole renderer projections, a flat parent/ordered-children item map, shared Favorites, per-space Pinned/Today roots, saved split items, archive snapshots and injectable time. Both place chrome below tab views and use separate native views for UI that must cover web content. Both specify lazy restored tabs, atomic versioned JSON persistence, one action table, CDP-based Page/webContents mapping, `sendInputEvent` for shortcut tests, destruction-event assertions and composited screenshots. That agreement is strong evidence for retaining this overall architecture.
