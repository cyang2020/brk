## Recommended base: B

B gives a future maintainer fewer lifecycle decisions to coordinate. The domain emits a complete desired page list, the engine converges to it, and views place stable surfaces using pure frame data. Its live/closing identity separation is a better foundation for a real CEF body than making the shell pair page creation, attachment, restoration and close calls. The separate engine and CEF targets also let UI workers implement against a stub. Keep B's reducer-owned key decisions, per-binding priorities, typed control protocol and explicit computed-versus-actual frame contract. B is the stronger shape, but neither candidate is ready to freeze for parallel implementation: the risks below include actual compiled defects and contradictions that fatal bodies currently conceal. No live CEF shutdown or display behavior was verified by this review.

## Grafts

1. Port A's metric inventory check from `Tests/BrkDomainTests/PureTests.swift` and its enumerable `MetricsTable`/`AnyMetric` approach in `Sources/BrkDomain/Metrics.swift`. Adapt it to B's grouped constants and validate source text against the grounding where practical. Preserve B's additional constant variants and confidence annotations.
2. Port A's validated split membership and orientation from `Sources/BrkDomain/Model.swift` and `Ops/Split.swift`. Put the membership invariant inside B's `SidebarTree`, including an atomic dissolve operation, so normalization never needs an invalid public intermediate state.
3. Port A's named/custom icon vocabulary and fuller theme controls from `Sources/BrkDomain/Model.swift` and `Theme.swift`. B currently has space emoji/SF Symbols and a reduced theme; retain A's per-item icons, wheel and separate noise/intensity where the anatomy calls for them.

Do not graft A's staged `PageHost`, its two-priority shortcut policy, or its upstream termination-hook patch. B can neutralize the existing Objective-C handler through `CEFApplication.setTerminateHandler(nil)`.

## Risks in the base

The first four findings below were exercised against compiled code in the disposable copy. The remaining findings concern specified contracts or unfinished bodies, and are not claims of observed runtime browser failures.

1. **Expose a narrow focus operation across the UI boundary.** `Sources/BrkApp/WindowController.swift` promises to focus the command-bar input, but `Sources/BrkUI/CommandBar/CommandBarView.swift:13` makes `input` internal and offers no public focus method. A BrkApp probe returning `root.commandBar.input` fails to compile with “inaccessible due to 'internal' protection level.” Add a public focus API on the root or bar, including rename/dialog focus, before freezing the interface.
2. **Keep the test clock forward-only.** `Sources/BrkApp/Clock.swift:26` adds any `Duration`, including negative values. A real scratch test demonstrated that advancing by minus ten seconds returns a time before the preceding reading. Clamp or reject negative advances at the clock boundary, as A's clock does.
3. **Protect item kind as well as hierarchy links.** `Sources/BrkDomain/SidebarTree.swift:149` exposes `update(_: (inout ItemBody) -> Void)`. A scratch test made a Favorites root, replaced its body with `.tab`, and observed a tab with no parent. Use case-specific payload updates or validate kind-preserving updates. The same file still represents tab children and split membership with unconstrained arrays.
4. **Reconcile the implemented overlay policy with its behavioral inventory.** `Sources/BrkDomain/Command.swift:214` returns false for both `keepsCommandBar` and `keepsArchive` on `.sidebar(.resize(width:))`. The scratch probe confirms those values, while the three sidebar-peek/resize cases in `Tests/BrkDomainTests/ReduceSpecTests.swift` require resizing to preserve the open overlays. Fix the policy before filling the reducer. `Suggest.rank`'s ordering contract also disagrees with several copied suggestion-test descriptions in `Tests/BrkUITests/SuggestSpecTests.swift`.
5. **Always execute effect-only transitions.** The usage recipe in `docs/design/swift/rationale.md` says `guard t.changed else { return t.keyHandled }`, and `Sources/BrkApp/AppStore.swift` explicitly documents unchanged -> no effects. Back, reload, copying a URL and quitting can emit effects without changing state. The Electron `reduce.test.ts` explicitly asserts unchanged state with nonempty effects for browsing commands. Gate projection/render on change, but execute effects regardless.
6. **Complete close identity, acknowledgment and timeout semantics.** `Sources/BrkCEF/CEFEngine.swift:133` must not let an old page's close callback remove or report closure for its new incarnation. The ordinary callback identity guard does not implement that close path. `ChromePage.swift` never currently emits `.closedByPage`, while `Rules/Tabs.swift` treats `.closed` as bookkeeping only; specify how page-initiated close removes domain demand. Both candidates also allow timeout -> `cef_shutdown` with browsers potentially still alive. A timeout must produce a controlled failure or another explicit terminal policy, not bypass the required OnBeforeClose condition.
7. **Make press identity stable and window-scoped.** `BrkDomain/KeyRouting.swift` stores one global pending chord and one `UInt64` last-dispatch id. `BrkCEF/ChromePage.swift` proposes a timestamp from `NSApp.currentEvent`, or zero, despite after-page delivery being asynchronous. Carry stable original-event identity through the bridge or define an equally precise correlation rule; include window/source/chord and test both menu/CEF orders, rapid presses, repeats, cross-window delivery and mouse menu choices. Verify modifier-release delivery on the display. These are acknowledged uncertainties, not solved guarantees.
8. **Finish the codec and storage contracts.** `Sources/BrkDomain/Codec.swift` refers to nonexistent `StoredFile`, `StoredDocV1.init(_:)`, `validated()` and migration bodies. Define the versioned envelope and conversion signatures now. `BrkApp/StateFile.swift` also needs a concrete way for synchronous `writeNow` to cancel/drain actor-owned pending writes without a later stale write overwriting the flush; `read()` currently conflates I/O failure with absence.
9. **Make the harness implementable through its allowed imports.** `BrkControl/Protocol.swift` exposes `evaluate(page:script:)`, but `BrkEngine/WebEngine.swift` and `BrkBase/Page.swift` expose no evaluation capability to the app-side executor. Add the narrow capability or revise the operation. Complete page-lifecycle logging at the engine boundary, including closing generations. The stub, runner, screenshots and report remain unfinished bodies; `BRK_ENGINE=stub swift run Brk` does not yet open a functioning shell.
10. **Make ownership disjoint and reserve the later-feature boundary.** Move W2's `Work.routeKey` out of W1's `Reduce.swift`; split W2/W3-owned functions out of `BrkLayout/WindowLayout.swift`; assign the shared dialog file one owner. `BrkUI` places all workers' internals in one importable target, so the scanner cannot enforce those internal boundaries. Define how persistent standard containers and ephemeral Little Arc/Peek/incognito containers enter the same reducer/projection pipeline. Profiles and per-profile Favorites are already represented; the other containers are not.

The metric requirement also needs an executable gate. Adding `public let judgeUnsourcedLayoutNumber = 123.0` to B's constants file still passed all seven architecture tests. `Metric`'s constructor forces a source only when the author chooses to use `Metric`.

## Design red-flag accounting

Counted by distinct category from the requested checklist, not by every instance. No temporal-decomposition flag is established in either candidate. Short app-command-to-effect routing is justified by target resolution and key policy, so it is not counted as a pass-through defect.

- **A, three categories.** Shallow module: `PageHost.swift` requires callers to coordinate create/show/layout/restore/close. Split ownership: the “Tree is the only hierarchy writer” rule in `Ops/Tree.swift` is not enforced on `Model.swift`'s writable parent/child fields. Hand-synced list: `Actions.swift` separately declares `ActionID` and table rows; `test_everyActionIDAppearsOnce` checks duplicates but not completeness.
- **B, two categories.** Importable internals: W2/W3/W4/W5 share `BrkUI`, exposing each worker's internal views to siblings within that target. Hand-synced list: `BrkBase/Keys.swift` declares individual static keys and separately maintains `Key.known`; a new static key can be omitted from the lookup list without an exhaustive check.

A's scanner weakness is independently proven: `@preconcurrency import AppKit` in a new BrkDomain file passed all eight architecture tests. B's real validator negative cases are substantially better, although its scan still is not a Swift parser.

## Convergence

Both choose opaque domain state, a pure reducer with injected time/id generation, a flat sidebar tree, ordered space roots, shared Favorites, archive snapshots, lazy restored pages, whole-view projections, atomic versioned JSON, sourced constants, procedural Metal themes, a shortcut table and socket-driven display scenarios. Both isolate CEF use, restore moved views before closing browsers, await close callbacks before runtime shutdown in the intended happy path, and recognize the private Chromium classes and quit crash as the first integration risks.

Both rationales still say “77 reducer tests.” The referenced current `electron-v1:src/domain/reduce.test.ts` has **81** test declarations. B reproduces those 81 as named stubs, then adds 14 cases from other domain test files. A has 85 named reducer-file cases with a less literal correspondence. The Electron e2e files have 10 done-predicate/smoke tests and 10 regression tests. A names 21 scenarios including clean quit; B names 24 including four native scenarios. R3's Cmd+click in B is the appropriate macOS adaptation of the Electron/Linux Ctrl+click. The sidebar-renderer crash scenario needs an explicit native replacement, not a claim of identical coverage.

Little Arc, Peek, profiles, incognito, extensions, Boosts, Easels, Notes, Live Folders, Air Traffic Control, PiP, captures, site controls, settings, onboarding and import all have entries in both rationales. Those entries describe extension plans; most are not frozen executable contracts. B's page/native-pane distinction and per-profile data reduce future changes, while A's orientation, icons and richer theme model are useful grafts.
